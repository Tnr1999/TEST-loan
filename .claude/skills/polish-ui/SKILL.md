# polish-ui — ขัดดีไซน์ UX/UI

ช่วยทำให้หน้าจอของระบบสินเชื่อรายวัน **สวยขึ้นและสม่ำเสมอ** ตามมาตรฐานโปรเจกต์

## ขั้นตอน

1. **อ่านมาตรฐานก่อนเสมอ:** `docs/DESIGN.md` (โทนสี, คอมโพเนนต์, กฎ UX) และ design tokens ใน `css/style.css` (`:root`)

2. **กำหนดขอบเขต:** ถ้าผู้ใช้ระบุหน้า/คอมโพเนนต์ (เช่น "หน้าลูกค้า", "การ์ด") โฟกัสที่นั่น — ถ้าไม่ระบุ ให้ถามว่าจะขัดหน้าไหน หรือเสนอไล่ทีละหน้า (dashboard → customers → payments → admin)

3. **ตรวจตามเช็กลิสต์** (จาก DESIGN.md) แล้วหาจุดที่ "ไม่สวย/ไม่เข้าชุด":
   - ใช้ค่าสี/ระยะดิบ แทนที่จะใช้ตัวแปร `--*`
   - สี semantic ผิดความหมาย (เขียว=สำเร็จ, เหลือง=เตือน, แดง=อันตราย)
   - ปุ่มกดเล็กกว่า 44px บนมือถือ / ระยะห่างไม่สม่ำเสมอ / จัดเรียงเพี้ยน
   - contrast ต่ำจนอ่านยาก
   - ล้น/ตัดบนจอแคบ ~360px
   - ขาด empty state, toast, หรือ confirm
   - สร้างคอมโพเนนต์ใหม่ทั้งที่มีของเดิม (`.btn`, `.card`, `.st`, `.crow`, `.vchip` ...)

4. **เสนอก่อนแก้:** สรุปจุดที่จะปรับเป็นลิสต์สั้นๆ (ปัญหา → วิธีแก้) ให้ผู้ใช้เห็นภาพ ถ้าผู้ใช้ตกลงค่อยลงมือ

5. **ลงมือแก้:** แก้ที่ `css/style.css` (สไตล์) หรือไฟล์ฟีเจอร์ใน `js/*.js` (โครง markup) — ห้ามแก้ตรรกะธุรกิจ, ห้ามแตะสูตรคำนวณ, คงพฤติกรรมเดิม

6. **ตรวจหลังแก้:** syntax JS ผ่าน (`node --check`), ไม่ทำ inline `onclick` พัง, ภาษาไทยครบ

## กฎเหล็ก

- **เปลี่ยนแค่รูปลักษณ์ ไม่เปลี่ยนพฤติกรรม/ตรรกะ** เว้นแต่ผู้ใช้ขอ
- ใช้ design tokens เสมอ ไม่ฮาร์ดโค้ดสี/ระยะ
- ใช้คอมโพเนนต์เดิมซ้ำก่อนสร้างใหม่
- มือถือมาก่อน · ภาษาไทยล้วน
- งานเสร็จ → commit บน branch `claude/...` → ให้ผู้ใช้ลอง Vercel Preview ก่อน merge
