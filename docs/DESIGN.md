# DESIGN.md — คู่มือ UX/UI ระบบสินเชื่อรายวัน

> มาตรฐานหน้าตา/การใช้งาน เพื่อให้ทุกหน้าจอ "เข้าธีมเดียวกัน ดูโปร ใช้ง่าย"
> ทั้งหมดอ้างอิง design tokens ใน `css/style.css` (`:root`) — **อย่าใส่ค่าสี/ระยะดิบ ใช้ตัวแปรเสมอ**

## 🎨 หลักคิด (ธีม)

- โทน **ดำ-ทอง หรูหรา**: ฐานดำอุ่น (`--bg:#0a0a09`) + **ทองโลหะ** (`--gold:#d4af37`) เป็นแอ็กเซนต์เดียว
- ภาษาไทยล้วน · มือถือมาก่อน (mobile-first) · เรียบ สะอาด เน้นอ่านง่ายสำหรับใช้งานเก็บเงินรายวัน
- **ทองคือพระเอกเดียว** — เลี่ยงสีแฟนซีอื่น นอกจากสี semantic · เทากลางๆ ใช้ **เทาอุ่น** (อิง `--muted`/`--border`) ไม่ใช่เทาอมน้ำเงิน
- ข้อยกเว้น: `--purple` (`.btn-purple`) ใช้เฉพาะปุ่ม "+ เพิ่มยอด" ในรายละเอียดลูกค้า เพื่อแยกจากปุ่มหลัก (ทอง) — ไม่ใช้สีนี้ที่อื่น

## สี (ใช้ผ่านตัวแปรเท่านั้น)

| ใช้ตอน | ตัวแปร |
|---|---|
| พื้นหลังหน้า / พื้นการ์ด | `--bg` / `--card`, `--card2` |
| เส้นขอบ | `--border`, `--border2` |
| ตัวอักษรหลัก / รอง / จาง | `--text` / `--text2` / `--muted` |
| ปุ่มหลัก/ไฮไลต์ (แอ็กเซนต์) | `--gold` (+ `--gold2` สว่างขึ้น, `--gold-dim` พื้นอ่อน) |
| **ตัวอักษรบนพื้นทอง** | `--on-gold` (ดำอุ่น) — ใช้ทุกที่ที่พื้นเป็นทอง **ห้ามใช้ `#fff`** |
| เทากลางๆ (พื้นป้าย/สถานะเฉยๆ) | `--muted-dim` (เทาอุ่นโปร่ง) |
| **สื่อความหมาย** สำเร็จ/เตือน/อันตราย/ข้อมูล | `--green` / `--amber` / `--red` / `--cyan` (มีคู่ `-dim` สำหรับพื้นอ่อน) |

**กฎสี semantic:** เขียว=จ่ายแล้ว/สำเร็จ · เหลือง/ส้ม=ต้องเก็บวันนี้/เตือน · แดง=ค้าง/ลบ/อันตราย · ใช้ให้ตรงความหมายเสมอ
**ป้าย role:** โทนทองล้วนไล่น้ำหนัก — เจ้าของ `.role-owner` (ทองเต็ม) → หัวหน้า `.role-head` (ทองจาง) → พนักงาน `.role-staff` (เทาอุ่น)

## ระยะ & มุมโค้ง

- มุมโค้ง: ปุ่มเล็ก `7–9px` · การ์ด `var(--radius-lg)` · modal `20px` (บน), ชิป `99px`
- ระยะภายในการ์ด ~`12–14px` · ช่องไฟระหว่างการ์ดในลิสต์ `10px`
- เงา: `--shadow` (การ์ด) · `--shadow-lg` (modal/ปุ่มลอย)

## ฟอนต์

- เนื้อหา: `--font-th` (Sarabun) · หัวข้อเด่น: `--font-serif` (Kanit) · ตัวเลข/รหัส: `--font-mono`
- ตัวเลขเงินใช้ `mono` + จัดชิดขวาในตาราง · เงินจัดรูปด้วย `fmt()` เสมอ (มี `฿` นำหน้า)

## 📐 Breakpoints (Responsive) — แบ่งด้วยความกว้างล้วน

> ข้อจำกัดการใช้งานจริง: **มือถือใช้แนวตั้งเท่านั้น · Tablet ใช้ได้ทั้งนอน/ตั้ง · PC นอนอย่างเดียว**
> เงื่อนไขแนวการวางถูกตอบด้วย "ความกว้าง" อยู่แล้ว → ไม่ต้องใช้ orientation/height (เปราะ+เทสต์ยาก)

| Tier | Media query | layout หลัก |
|---|---|---|
| 🖥️ **PC** (นอน) | `@media (min-width:1024px)` *(ฐาน CSS)* | ตาราง · nav บนหัว · dashboard 2 คอลัมน์ |
| 📲 **Tablet** (นอน/ตั้ง) | `@media (min-width:768px) and (max-width:1023px)` | ตาราง · nav บนหัว · กระชับลงเล็กน้อย |
| 📱 **มือถือ** (ตั้งเท่านั้น) | `@media (max-width:767px)` | การ์ด 1 คอลัมน์ · bottom nav · ค่า default |

- **Tablet นอน** กว้าง ≥1024px (เช่น iPad นอน) → ตกไปใช้ layout PC ซึ่งเหมาะอยู่แล้ว (ตาราง)
- **ไม่รองรับมือถือแนวนอน** โดยตั้งใจ (ถ้าหมุนนอนจะได้ layout Tablet/ตาราง)
- ลำดับใน CSS: บล็อก `≥768` (ซ่อนการ์ด) → `768–1023` (Tablet) → `≤767` (มือถือ)

**class ช่วยซ่อน/แสดง:**
- `.desktop-only` → แสดงบน **PC + Tablet** (ตาราง) · ซ่อนบนมือถือ
- `.mobile-only` → แสดงบน **มือถือ** (การ์ด) · ซ่อนบน PC + Tablet

## กฎ UX (สำคัญต่อการใช้งานจริง)

1. **มือถือมาก่อน** — ทุกหน้าต้องใช้ดีบนจอแคบ (พนักงานเก็บเงินใช้มือถือ)
2. **ปุ่มกดบนมือถือ ≥ 44px** — กดง่าย ไม่พลาด
3. **PC/Tablet ใช้ตาราง · มือถือทุกแนวใช้การ์ด** (`.desktop-only` / `.mobile-only` — ดูตาราง Breakpoints)
4. **เน้นงานวันนี้** — สิ่งที่ต้องทำ (เก็บเงินวันนี้/ค้าง) ต้องเด่นและลอยขึ้นบนสุด
5. **ลดการพิมพ์** — ใช้ชิป/ปุ่มลัด/ค่า default ที่ฉลาด (เช่น default = ต้องเก็บวันนี้)
6. **feedback ทุก action** — บันทึก/ลบ ต้องมี `toast()` ยืนยัน · ลบต้อง `showConfirm()` ก่อน
7. **สถานะ empty/loading** ต้องไม่ดูเหมือนแอปพัง (มีข้อความ + ทางออก)
8. **contrast พอ** — อย่าวางตัวอักษร `--muted` บนพื้นเข้มจนอ่านไม่ออก

- [ ] มี empty state + toast/confirm ครบ
